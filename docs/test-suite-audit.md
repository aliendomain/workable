# Test Suite Audit

Last updated: 2026-06-01

## Scope

This audit tracks the .NET solution test-suite repair work after the large refactor. It focuses on service and service-like classes: types named `Service`, `Manager`, `Orchestrator`, `Provider`, `Factory`, `Handler`, `Processor`, `Coordinator`, `Repository`, `Client`, `Adapter`, plus implementations of service-style interfaces.

The solution also contains a sample host, performance harness, and SQL Server CLI. The first coverage pass prioritizes library/runtime projects and the SQL Server integration runtime because those are exercised by the solution tests.

## Test Commands

Run .NET tests outside the Codex sandbox. `AGENTS.md` documents that sandboxed `dotnet test` can stall in MSBuild node orchestration.

Current full-suite command:

```powershell
dotnet test .\Workable.slnx --no-restore --logger "console;verbosity=minimal" --blame-hang-timeout 2m
```

Focused commands:

```powershell
dotnet test tests\Workable.Tests\Workable.Tests.csproj --no-restore --logger "console;verbosity=minimal" --blame-hang-timeout 2m
dotnet test tests\extensions\sqlserver\Workable.SqlServer.Tests\Workable.SqlServer.Tests.csproj --no-restore --logger "console;verbosity=minimal" --blame-hang-timeout 2m
```

## Current Pass/Fail State

Last full run:

```text
dotnet test .\Workable.slnx --no-restore --logger "console;verbosity=minimal" --blame-hang-timeout 2m
Passed: Workable.Tests, 1010 passed
Passed: Workable.SqlServer.Tests, 45 passed
Overall: 1055 passed, 0 failed
```

The SQL Server integration tests previously failed because their test systems used the production default authorization requirement while the tests used direct system access. That was repaired by adding the SQL Server test-only `AddWorkableSystem` wrapper that opts those test registrations out of authorization, matching the main test project convention.
